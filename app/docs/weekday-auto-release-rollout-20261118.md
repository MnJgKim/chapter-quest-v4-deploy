# Chapter Quest V4 요일별 자동 공개 운영 적용안

2026년 11월 18일 서울 기준. 운영 변경은 별도 승인 후 실행한다. SQL 및 격리 CI 기준 커밋은 `884312f3e530d4c7ebfd9023ad6fac67c13e2033`이다.

## 운영 읽기 전용 확인

- 계정 `b7c90ec0…`은 Auth에 존재하고 일정 소유 부모에게 등록돼 있다. 이 계정으로 청구된 초대 기록이 없어 서우 본인이라는 근거는 확인되지 않았다. 해당 부모가 확인한 전체 계정 ID를 사용한다.
- 11월 23·25·26·30일과 12월 2·3·7·9·10·14일의 10건 모두 서울 시간대, 기존 배정, 준비된 PDF, 공개 활동, 기존 공개 플래그를 확인했다. 해당 10건의 제출은 0건이다.
- 서진과 시우의 승인·등록 계정을 확인했다. 각각 배정·일정·배정된 준비 완료 PDF가 0건이다. 서진에게 화·수·금 정책만 등록하고, 두 학생의 챕터는 배정하지 않는다. 시우의 정책 행은 추후 승인된 요일이 생길 때 등록한다.

## Cloudflare 출시 차단 사항

운영 HTML이 불러오는 [학생 API 자산](https://chapter-quest-v4.roscabear.workers.dev/js/student-api.js)을 읽기 전용으로 확인했다. 운영본은 공개 목록 RPC만 호출한다. 개발본에는 자동 공개 RPC 호출이 연결돼 있다. 운영 자산의 SHA-256은 `1ae47ffb4f72b6ce21f3ac7a433dc9bcdaefa6e278ba1cd16e4c7f8a7df76e87`이며 개발본은 `857f1bd58670aa5bd0fb7415338fde641ae7bb06defec83dc4bc2a49ad06110d`이다. 공개 자산 비교는 Worker 배포 버전이나 복구 가능 여부의 확인을 대신할 수 없다.

운영·Stage 현재 버전과 자산 목록을 확인하고 복구 가능성을 검증할 때까지 Worker 반영을 보류한다. 기존 배포본을 기준으로 학생 API 변경만 검토한다. DB RPC 설치 후 정책·큐가 비어 있는 상태에서 별도 승인된 자산 반영과 확인을 완료한 다음 정책을 등록한다. 기존 10건은 이미 공개 플래그가 있어 Cloudflare 변경 전에도 기존 날짜 기준으로 열린다.

## 승인 후 적용

1. 운영 프로젝트와 역할을 다시 확인한다. `postgres` 소유의 실제 운영 RPC 정의 및 권한을 파일로 내보낸다. 최소 대상은 `cq_v4_parent_schedule_lesson(uuid,uuid,date)`, `cq_v4_parent_set_lesson_release(uuid,uuid,boolean)`, `cq_v4_submit_answers(uuid,jsonb)`이다. `pg_get_functiondef(oid)`는 각 정의에 종결 세미콜론을 붙여 저장하고, 소유자와 ACL도 함께 기록한다. 같은 시점에 대상 학생의 일정 키·날짜·시간대·공개 플래그, 제출 식별자와 개수, 기존 정책·큐 존재 여부를 읽기 전용으로 보관한다. 파일은 접근 제한된 위치에 보관한다. 제출 답안이나 녹음 파일을 복사할 필요는 없다.
2. 배포된 학생 자산에서 목록을 열기 전 `cq_v4_ensure_today_approved_lesson()` 호출이 실제로 연결되는지 읽기 전용으로 확인한다. 해당 연결이 있으면 Worker는 그대로 둔다. 자산 수정이 필요한 경우 별도 승인 전에 중단한다. Worker 변경 절차에는 운영·Stage 각각의 현재 버전 식별자, 자산 해시 및 이전 버전으로 되돌릴 수 있는지 확인하는 단계가 필요하다.
3. 운영 DB에서 기존 프로젝트·스키마·RPC 정의가 검토본과 일치하는지 확인하고, 승인된 낮은 사용량 시간대에 오류 중단을 켠 관리 세션으로 아래 파일을 순서대로 실행한다. DDL 대기 시간이 길어지면 중단하고 상태를 확인한다. 3번 파일 자체가 트랜잭션이며 기존 공개 판정 RPC는 교체하지 않는다. 4번 전까지 정책과 큐가 비어 있어 자동 공개가 발생하지 않는다.
   1. `app/sql/student-weekday-policy-v1.REVIEW-ONLY.sql`
   2. `app/sql/approved-chapter-queue-v1.REVIEW-ONLY.sql`
   3. `app/sql/student-auto-release-existing-schedule.REVIEW-ONLY.sql`
   4. `app/sql/student-weekday-policy-initial-config.REVIEW-ONLY.sql`. 검증된 전체 학생·부모 UUID 네 개와 `weekday_effective_from=2026-11-23`을 psql 변수로 넘긴다. 예상 정책은 서우 `{1,3,4}`, 서진 `{2,3,5}`이다. 두 정책 행 및 적용 날짜를 재조회한다. 기존 행이 발견되면 덮어쓰지 않고 승인 내용과 일치 여부를 확인한다.
4. 이번 적용에서는 승인 큐를 비워 둔다. 기존 10건은 이미 배정·예약돼 있어 큐가 필요 없다. 이후 빈 날짜에 이어서 공개할 챕터는 명시적으로 승인되고 이미 배정된 순번만 별도로 등록할 수 있다.

## 11월 23일 서울 자정 이후 예상 동작

- 기존 10건은 각 수업일 서울 자정부터 기존 서버의 `released_at IS NOT NULL` 및 수업 날짜 조건으로 학습할 수 있다. 적용 시 기존 공개 시각이나 날짜를 다시 쓰지 않는다.
- 기존 일정에는 자동 공개 보류 기본값을 추가하므로 기존 비공개와 미공개 상태가 모두 보존된다. 이미 공개 플래그가 있는 이월·요일 예외 일정은 기존 날짜 조건으로 열린다. 앞으로 부모가 숨긴 행은 자동으로 재공개되지 않는다.
- 서진의 첫 정책 요일은 11월 24일이다. 준비된 PDF와 승인 큐·배정이 없는 동안 공개할 일정이 생성되지 않는다. 시우에게는 새 정책이나 일정이 생성되지 않는다.

## 적용 후 확인과 복구

- 카탈로그에서 정책·큐의 RLS가 활성 상태인지, `anon`·`authenticated` 직접 쓰기가 거부되는지, 인증 사용자만 자동화 진입점을 실행할 수 있는지 확인한다. 승인 순번 조회 함수는 호출자 자신의 큐만 반환해야 한다. 시간 입력, 잠금, 트리거 함수에는 두 클라이언트 역할의 실행 권한이 없어야 한다.
- 적용 전후 10건의 챕터 키·날짜·시간대·공개 플래그와 기존 제출 식별자·개수를 비교한다. 승인 후 첫 해당일에는 기존 학생 읽기 경로로 당일 챕터만 새로 보이고 다음 날짜는 닫혀 있는지 확인한다. 서진과 시우의 배정 및 일정 건수도 확인한다. 운영 확인을 위해 테스트 제출·녹음·학생 배정을 만들지 않는다.
- 이상 시 먼저 이날 설치한 두 정책의 `enabled`를 false로 바꿔 후속 자동 처리를 중단한다. 이미 실행 중인 호출이 끝난 후 일정과 공개 플래그를 다시 확인한다. 기존 정상 공개는 계속 동작한다.
- RPC 교체까지 되돌려야 한다면 한 트랜잭션에서 자동 공개 진입점을 같은 시그니처의 `SELECT NULL::uuid` 함수로 교체하고, 백업한 부모 일정·공개 및 제출 RPC 정의와 권한을 복원한다. 인증 학생 앱의 후속 공개 목록 조회는 유지된다. 정책·큐·보류 열은 복구 중 보존한다.
- 적용 이후 발생한 일정·공개 변경은 사전 스냅샷과 비교해 개별 확인한다. 학생의 실제 활동이 있을 수 있으므로 전역 DB 복원이나 일정·제출 일괄 삭제를 하지 않는다. Worker 변경을 별도로 승인·실행했다면 이전 Worker 버전 복구 후 자산 해시와 읽기 경로를 확인한다.
