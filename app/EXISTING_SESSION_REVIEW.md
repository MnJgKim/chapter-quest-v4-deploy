# 기존 익명 학생 세션 확인 후보 기능

이 문서는 일반적인 코드 동작을 설명하며 실제 계정 정보는 포함하지 않는다. 운영 적용 전이다.

현재 이메일 로그인 UI는 이전 SDK 세션을 자동으로 읽지 않는다. 로그인 입력창만 보인다고 기존 계정 삭제나 저장 세션 소실을 판단할 수 없다.

후보 버튼은 명시적으로 누를 때만 현재 설정 프로젝트의 표준 SDK localStorage 키를 읽는다. GET /auth/v1/user로 실제 익명 사용자 ID를 확인하고, 그 ID에 대한 RLS 적용 enrollment 조회가 정확히 한 건일 때 메모리 세션으로 이어간다. 배정 조회는 기존 학생 RPC를 사용한다. 저장된 사용자 객체나 JWT 내용으로 신원을 확정하지 않는다.

계정 생성·변환·재초대·토큰 갱신·저장소 삭제를 실행하지 않는다. 만료되면 중단한다. 지원하는 저장 형식이 없거나 다른 브라우저·쿠키에만 세션이 있으면 복구 성공을 주장하지 않는다. 이 기능은 만료된 익명 계정의 완전한 복구 기능이 아니다. 기존 UID를 유지하는 갱신이나 계정 연결은 별도 승인 및 검증 대상이다.

실기기에서는 기존 브라우저와 프로필을 보존한다. 승인된 후보 버전에서 읽기 확인을 실행한 후, 계정 확인번호를 부모 화면과 대조하고 배정 목록을 조회한다. 인증 토큰·비밀번호·저장소 원문을 공유하지 않는다. 운영에는 이 버튼이 아직 없으므로 배포 전 운영 화면에서 실행하도록 안내하지 않는다.

검증: 합성 단위 테스트 13개, 격리 브라우저 검사 7개(360×800, 800×1280, 1280×800 포함). 실제 기기의 저장 기록, 실제 Auth/RLS 응답과 장기 세션 복구는 미검증.

참고: Supabase anonymous sign-in 문서와 changelog를 2026-11-12 확인했다. 문서는 로그아웃·브라우저 데이터 삭제·다른 기기에서 익명 계정에 접근할 수 없음을 명시한다. 새 anonymous sign-in은 기존 계정 복구로 사용하지 않는다.

## 상태 표시 보완
동일 UID로 이어간 뒤 읽기 전용 배정 RPC를 자동 호출한다. 인증·부모 연결과 배정 조회 성공/실패를 구분한다. 학생에게 보이는 승인·배정 자료 0개로 부모의 전체 승인 상태를 추정하지 않는다. 기존 연결 자체는 승인 초대 이력과 동일하다고 단정하지 않는다. 안내 및 신규 상태 분기를 포함한 격리 브라우저 검사 10개를 추가 확인했다.
