# 기존 익명 학생 계정을 보존하는 로그인·복구 검토

운영 SELECT 조회로 부모·학생 연결 1건, 익명 학생 Auth 존재/이메일 없음, 이메일 인증된 부모 관리자를 다시 확인했습니다. 이 학생이 서우인지는 확인되지 않았습니다. 계정·연결·인증 세션을 변경하거나 운영 계정으로 로그인하지 않았습니다.

2026-11-11 확인한 공식 문서:
- https://supabase.com/docs/guides/auth/users
- https://supabase.com/docs/guides/auth/auth-anonymous

익명 사용자도 고유 UID와 authenticated 역할을 갖습니다. 단순히 새로 익명 로그인하면 새 사용자가 만들어지므로 기존 UID 복구로 취급하지 않습니다. 사용자 편집 가능 이름/메타데이터를 권한의 근거로 사용하지 않습니다.

| 상태 | 기존 계정을 보존하는 검토 경로 | 현재 상태 |
| --- | --- | --- |
| 원래 기기에 유효한 세션이 있음 | 해당 기기 안에서 서버 `getUser()`로 기존 UID·부모 연결을 확인하고 같은 세션을 이어가는 방안을 검토합니다. 토큰을 채팅/파일로 옮기지 않습니다. 운영 세션 갱신도 이 작업에서는 실행하지 않습니다. | 실제 기기 세션 존재 미확인. 현재 후보는 이메일 로그인 방식이며 익명 세션 이어가기 UI는 구현·운영 검증하지 않았습니다. |
| 기존 익명 세션으로 로그인 가능하고 이메일 연결을 원함 | 공식 문서의 manual linking 활성화 전제와 유효한 기존 세션을 확인한 뒤 `updateUser({email})`로 같은 익명 사용자에 이메일을 연결하고, 이메일을 검증한 뒤 비밀번호를 추가하는 절차가 가능합니다. 신규 가입 대신 기존 UID 유지 여부를 확인해야 합니다. 기존 이메일 계정과 충돌하면 자동 합치거나 삭제하지 않습니다. | Auth/계정 변경이므로 별도 승인 필요. 실행하지 않았습니다. |
| 로그아웃·브라우저 데이터 삭제·다른 기기로 세션을 잃음 | 공식 문서상 그 익명 사용자는 일반적인 재로그인을 할 수 없습니다. 부모의 실제 소유권과 기존 UID를 확인한 뒤 관리자 지원 가능성을 별도 검토합니다. 정상 비밀번호 재설정이나 새 익명 로그인을 복구로 주장하지 않습니다. | 자동 복구를 보장하거나 구현했다고 표시하지 않습니다. |

비밀번호·API 비밀키·세션 토큰을 채팅으로 요청하지 않습니다. 실제 계정이 서우임을 확인하기 전 이메일 전환·계정 대체·새 연결은 실행하지 않습니다. 운영 변경이 필요한 안은 변경 범위·위험·복구 방법과 UID/기존 학습 데이터 보존 검증을 준비한 뒤 승인받아야 합니다.

운영의 manual linking 설정과 이메일 전달·검증은 아직 확인하지 않았습니다. 설정 변경도 운영 변경이므로 승인 없이 켜지 않습니다.

## 원래 기기에서의 최소 보존·확인 순서

1. 서우가 사용하던 **같은 기기·같은 브라우저·같은 프로필·같은 사이트 주소**를 유지합니다. Samsung Internet과 Chrome, 일반 창과 시크릿 창은 저장소가 다릅니다. 브라우저 데이터/사이트 저장소를 지우거나 로그아웃·재설치·새 익명 로그인·새 초대를 하지 않습니다.
2. 학생 화면이 이미 열려 있으면 이름만으로 동일 계정이라고 판단하지 않습니다. 사용자에게 토큰을 복사하거나 개발자 도구 명령을 입력하게 하지 않습니다. 새 코드 배포도 세션 복구의 전제라고 가정하지 않습니다.
3. 승인된 기기 점검 시 개발자가 기존 세션의 존재를 기기 안에서 확인하고, 자동 세션 갱신·새 사용자 생성 없이 기존 access token으로 Auth `getUser()`와 현재 부모 연결을 대조하는 읽기 검사를 준비합니다. 토큰 값은 출력·전송·문서화하지 않습니다. 액세스 토큰 만료와 계정 삭제를 혼동하지 않습니다.
4. 갱신이 필요하면 refresh token이 남아 있어도 `refreshSession`/`setSession`은 Auth 세션 상태를 변경할 수 있으므로 이번 읽기 전용 범위에서는 실행하지 않습니다. 기존 UID 유지·실패 시 중단·토큰 비노출을 포함한 최소 갱신 계획을 별도 승인받아야 합니다. 검증하지 않은 자동 복구를 약속하지 않습니다.
5. 유효한 기존 세션을 찾지 못하면 즉시 중단합니다. 새 익명 사용자를 만들어 기존 계정처럼 대체하거나 데이터/부모 연결을 옮기지 않습니다. 이메일 전환도 유효한 기존 세션·공식 linking 설정·소유권 확인과 별도 승인이 필요합니다.

운영 연결 1건과 익명/이메일·전화번호 없음, 인증된 부모 관리자, 게시·배정 0건을 다시 SELECT로 확인했습니다. 서버의 이름 `서우` 행은 0건이므로 이 연결이 서우라는 판정은 보류합니다. 원래 기기에는 접근하지 않았으며 세션 유효성·refresh token 보유 여부는 미검증입니다. 최신 공식 익명 Auth 문서도 로그아웃/데이터 삭제/다른 기기에서 재접근할 수 없음을 명시합니다. 이번 점검은 운영 로그인·갱신·계정 변경을 수행하지 않았습니다.
