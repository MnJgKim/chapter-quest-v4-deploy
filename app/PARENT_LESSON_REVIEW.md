# Parent lesson review and approved assignment — candidate only

The parent draft editor now permits changes to question text, choices/correct index, model answers, vocabulary/meaning/examples, writing/speaking prompts and private evidence. Optional `parentReview` metadata records file-page references, printed labels and notes per question/word. Imported legacy drafts remain supported; parents can add evidence in the editor. Evidence-bearing approval requires complete evidence and explicit source confirmation, which any review edit clears.

Review edits persist as a parent-side pending draft and survive reload without approving questions. Reopening saved content for changes invalidates local approval. Approval hashes include private evidence when present; changing it invalidates the receipt. Validation and asynchronous identity/chapter/content checks precede committing the approved snapshot. A failed save restores the previous local record. Local approval does not publish or assign automatically.

Private evidence is not added to student questions or publication RPC parameters. The existing question whitelist splits correct indices/model answers into the protected parent answer key. Evidence remains in the parent local state/private parent backup or privately supplied JSON; it is not a new shared server table. Local device demo/storage is not an authentication boundary. Use server student mode and separate parent storage/profile for private preparation; do not mistake a demo name selector for server identity.

Server hardening: `cq-v4-pdf-parent`'s existing direct `assign` action now also requires a published activity and a matching parent-owned approval bound to the same verified PDF and content hash, after checking parent role and enrollment. Missing or failed checks make no assignment write. Existing publication RPC already requires an owned bound approval and current enrollment. Tests cover student/foreign/missing approvals and unenrolled assignment. RLS/Storage policies are not broadened.

Development verification separates synthetic local Auth/Storage/Edge tests from actual privately supplied lesson browser tests using mock HTTP and fake microphone. Actual source, drafts, answers and account observations remain outside this public repository. Content review/approval by the real parent, existing anonymous account access, hardware microphone and operating execution remain unverified until separately performed.

Production scope is not approved or applied: the frontend review controls and parent Edge assignment tightening join the existing reviewed release candidates. Existing PDF, users and enrollment are preserved. Before approval, capture the current source/JWT settings, server definitions and prior frontend version; confirm compatible SQL/Edge/frontend order and free account capacity. File ranges may add review metadata and publication adds lesson/assignment records, so these require explicit operating-write authorization. Restoring code does not undo existing submissions/assignments; preserve original/derived files and all account/answer/audio rows, and do not blindly restore older security behavior. Do not apply local bootstrap or historical rollback scripts.
