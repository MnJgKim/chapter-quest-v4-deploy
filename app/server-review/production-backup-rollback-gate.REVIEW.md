## 3. 운영 적용 순서 (명시적 승인 후)
1. 승인된 스키마/인덱스·RPC를 종속성 순서대로 적용하고 결과 검증
2. 부모 관리자 UI를 별도 stage에서 읽기 전용으로 확인 (stage도 운영 DB 공유)
3. 부모별 자동 공개 정책은 **기본 비활성** 상태로 유지; 승인된 학생별 요일만 설정
4. 기존 일정은 변경하지 않고, 실제 승인된 챕터만 빈 날짜에 배정
5. 운영 Worker/정적 파일 배포 후 학생·부모 계정으로 학습/제출/결과 확인
6. 모바일·갤럭시 태블릿 실제 기기 검증

## 4. 장애 복구
- 새 자동 정책을 중단하고 신규 예약 쓰기를 중지한다.
- 운영 Worker/정적 파일을 기록한 이전 버전으로 롤백한다.
- DB 복원은 새 스키마에만 한정되는지, 전체 DB 복원이 필요한지 **차이를 비교**한 후 결정한다. 무조건 전체 복원하면 그 사이 발생한 학생 제출을 잃을 수 있다.
- 복구 후 기존 제출·예약·PDF 파일 개수와 읽기/쓰기 권한을 재검증한다.
